## Constitutional boundary

The v0.12 rights/access contract explicitly separates **chat-session study authorization** from **local runtime conformance**. After the current terms are presented, exact digest-bound `I ACCEPT` in a clean admission context authorizes substantive AI study in that same chat/session; `PROBE`, `INITIALIZE` and `ACTIVE` are required only for the separate official/conforming local-runtime path.

A completed pre-acceptance acquisition remains a non-retroactive breach. Re-presenting the current terms and receiving a new exact current-session acceptance may move only to `REMEDIATED_ACCEPTED`: prospective same-session read/list/search study is allowed, while clone/fetch/materialization for a conforming local runtime remains blocked until a fresh clean admission context.

`chat-study authorization != clean admission != runtime readiness != semantic output != evidence != permission != approval != grant != lease != execution != world truth`

S10 adds no authority and no new epistemic persistence. It exposes the already-persisted Surface B JSON/DOCX as a bounded, read-only, progressively disclosed epistemic lens inside the S9 product workspace.

After ACTIVE, every semantic iKant output remains one HSPv2 envelope rendered **inside the same sealed dashboard frame** and acknowledged by the exact-byte egress protocol. S8 still owns the paired runtime-session single writer and S9 remains the chat-first human product shell.

S10 inspection is permitted only for the current S8 writer after the exact last frame ACK and while no sealed frame is pending. Reads are runtime-session/cycle-bound, generated-path-only and bounded. The UI never touches `#dashboard`, never creates a second semantic message channel and never opens a browser-to-model protocol.

`PRODUCT_CONTRACT.json` is the cumulative product-slice manifest; `ikant.invariants` is the cross-cutting invariant registry; `scripts/product_boundary.py` derives all registered slices and executes the current slice's contract-declared saturation budget without per-version workflow accretion.

## Chat-session study path

A web-browsing/chat assistant does not need to become a local iKant runtime before it can study the repository under the owner's terms:

```text
orientation capsule -> present current T&C digest -> exact current-session I ACCEPT -> same-session AI study
```

If the host already exposed repository content before the gate, the breach is retained rather than erased:

```text
BREACHED -> re-present current T&C -> exact current-session I ACCEPT -> REMEDIATED_ACCEPTED -> prospective chat study only
```

That remediated path cannot claim clean admission or official/conforming iKant.
