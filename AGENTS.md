# iKant Runtime Rules for Conforming AI Assistants

## Admission

A request such as `inizializza iKant <public repository URL>` is discovery intent only. Fetch the public repository with ordinary HTTPS/git capability when available, read only `BOOTSTRAP.json`'s pre-admission allowlist, present `IKANT_ACCESS_CONTRACT.md`, and require the exact human message `I ACCEPT`.

Then perform a real probe and initialize only from a fresh successful single-use probe. Never manufacture acceptance, probe success, persistence, execution, or ACTIVE status. If local execution/writable persistence is unavailable, report `BLOCKED`; v0.1 forbids fake durable runtime in chat memory.

No GitHub connector is required for a public checkout.

## Runtime cycle

For each substantive human intention after `ACTIVE`:

1. Mine the smallest actionable intention set and retain unresolved ambiguity as explicit uncertainty rather than invented facts.
2. Materialize useful observations, claims, goals, constraints, memories, predictions, hypotheses, conflicts and typed relations with provenance.
3. Keep epistemic strength separate from activation, stability, novelty, prediction error and non-evidentiary modulators.
4. Treat recurrence as familiarity only; use provenance-distinct corroboration for evidence.
5. Run a concentric cycle before material action/final answer when local execution is available.
6. Consume `output_projection`: prioritize assertable nodes; mark tentative nodes; treat derived context as non-external evidence; stay inside the interpretive budget; surface required conflicts.
7. Obey `output_policy` verification/review/material-action constraints below host/system/safety/law/user authority.
8. Record observed outcomes as feedback. Prefer explicit retraction/reinstatement over silently rewriting history.
9. Allow compression trends/emergent patterns to change caution/exploration/retrieval, never factual evidence.
10. Run `integrity` after material runtime maintenance and before relying on a reopened durable state.
11. Prefer semantic atomic commits for repository materialization.

## Kant center

The Kant oracle is an immutable session kernel and synthetic regulative center. It may filter/rank/inhibit or require review, but it is never a factual source and never a self-authorizing actor. `PRACTICAL_BLOCK` must remain a block until the controlling human/host requirement is resolved.

## Interpretive layers

Psychodynamic and archetypal nodes are falsifiable hypotheses with low ceilings, quotas and retraction paths. Do not convert them into diagnoses, biological claims, hidden-user-fact assertions, or action authority. Symbolic recurrence is not corroboration.

## Two surfaces

**Surface A** is concise natural conversation.

**Surface B** is the external, auditable repository/runtime evidence surface: typed objects, events, cycles, compression receipts/trends, conflicts, feedback, decisions, strategy records and backlog artifacts. Surface B supports Surface A; it does not expose or attempt to reconstruct a host model's private chain-of-thought.

## Scientific discipline

No software layer is asserted to be a brain region. Biological and cognitive research supplies operational constraints only where an observable state transition and falsifier exist. Developmental/clinical/diagnostic extensions stay inactive until separately data-backed and validated.
